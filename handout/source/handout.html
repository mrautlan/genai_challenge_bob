Working with Bob

Controls · Context · Costs

✋ Approvals: you are the pilot

Before Bob edits a file or runs a command, it shows an approval card:

  • Approve: allow this one action
  • Approve for task: allow this kind of action for the rest of the task
  • Edit command: change a command before it runs
  • Or just reply in the chat to correct Bob’s course

Read the diff before approving. Does it change only what you asked for?

⏪ Rollback: your undo button

Bob takes a snapshot when a task starts and before every file change.

  • Hover over one of your messages → click the rollback button to restore the files to that point
  • Or restore a single file in Changed files
  • Only changes made by Bob are captured, and unsaved edits get overwritten

Rollback makes it safe to experiment boldly.

🎯 Give context with @ mentions

Type @ in the chat input. Pointing Bob at the exact thing is faster, cheaper and more precise than describing it.

MentionWhat Bob gets
@/index.htmlThe content of a file. Paths start with / from the folder you opened.
@/grades.py:10-25Only lines 10 to 25 of a file
@/srcThe files of a folder (not recursive, no trailing slash)
@problemsErrors and warnings from the Problems panel
@terminalThe last terminal command and its output
@git-changesYour uncommitted changes (Git repositories only)
@https://…The content of a web page, e.g. documentation
⌘/Ctrl + LSelect code in the editor and press this to add the selection to the chat

🪙 Bobcoins: use them wisely

Your trial includes 50 Bobcoins for 30 days. Every task Bob works on uses some, and big tasks and long chats use more.

  • Start a new chat for a new topic
  • Use small, focused prompts, not “build everything”
  • Point to files with @ instead of “look at the whole project”
  • If Bob fails twice, stop and rethink instead of retrying

🔐 Auto-approve: keep it off today

The Permissions button next to the mode selector lets Bob act without asking, per tool group (read, edit, execute, …).

Turning it on is convenient, but it bypasses confirmation prompts and gives Bob direct access to your system. In real projects, only auto-approve low-risk actions, such as reading files.

💡 Type / in the chat to discover built-in commands such as /init and /review.

⭐ Guardrails: context, rules & custom modes

.bob/rules/*.mdTeam rules that Bob follows in every mode. Files are read in alphabetical order, e.g. 01-team-rules.md.
.bob/rules-ask/ …Rules for one mode only: rules-{mode-slug}, e.g. rules-plan, rules-agent
.bob/custom_modes.yamlYour own modes, each with a role, instructions and allowed tools. Also available under Settings → Modes.
AGENTS.mdLives in the project root and is loaded automatically: project knowledge for every chat.

These are plain files, so a team can commit them to Git and everyone gets the same Bob. Examples: bonus-make-bob-yours/ in the repo.

Bob can explain Bob. In Ask mode, questions about Bob itself are looked up in the official documentation, for example: “How do I create a custom mode?” or “Where do rules files go?” · Docs: bob.ibm.com/docs/ide

Prompting a coding agent

Context engineering · Examples · Rules

🔀 What changes compared to prompting a chatbot

It acts.Prompts have side effects on your files. Set boundaries: what may change, and what must not.
It gathers its own context.Point it at the right files with @. Store lasting knowledge in rules and AGENTS.md instead of repeating it.
It works in many steps.Say how “done” is verified (tests, acceptance criteria), or the agent will decide that for itself.

📏 Eight rules for working with coding agents

  1. One task per prompt. For big things, plan first and then build step by step.
  2. Be explicit about constraints: language, files, libraries, what must not change.
  3. Point, don’t describe: use @/file, @problems, @terminal.
  4. Define “done”: tests pass, a feature works, the output looks like X.
  5. Report bugs like a pro: steps → expected → actual → error message.
  6. Ask for the why: “Explain the root cause before fixing.” You learn more and catch wrong guesses.
  7. Verify everything. Run it, click it, check the numbers by hand. Agents can be confidently wrong.
  8. Going in circles? Stop, roll back, add context (error, expected behaviour), or start a new chat.

🚀 Prompt boosters: add them to any prompt

Ask me up to 3 questions first. Show me your plan and wait for my OK. Only change X. Don’t touch anything else. Do not change any files. Run the tests afterwards. Tell me how to test it. Summarize what you changed in 3 bullets.

Prompt cheat sheet

Copy · Adapt · Paste

🔎 Understand Ask

Explain @/grades.py like I’m new to the team: purpose, inputs, outputs, step by step.
Where in this project is the timer handled? What would break if I changed it?

🗺️ Plan Plan

I want to build [X]. Constraints: [...]. Ask me up to 3 clarifying questions, then write the plan to PLAN.md.
Split @/PLAN.md into small steps that I can test one by one.

🛠️ Build Agent

Implement only step 1 of @/PLAN.md. Then tell me how to test it.
Add a dark-mode toggle that remembers the choice. Don’t change anything else.

🐛 Debug Agent

Bug: [steps]. Expected: [...]. Actual: [...]. Explain the root cause before you fix it.
@terminal Why did this command fail? Fix it.

🔍 Review Ask

Review @/index.html for bugs, security and accessibility issues. Table sorted by severity. Do not change files.

🧪 Test Agent

Write unit tests for [function/rules] including edge cases. Run them and summarize the failures. Don’t fix anything yet.

✨ Refactor Agent

Refactor @/grades.py for readability: descriptive names, small functions, no globals. Behaviour must stay identical. Run the tests after.

🎓 Learn Ask

Why did you choose this approach? Name two alternatives and their trade-offs.
Quiz me with 3 questions about the code you just wrote.

🧯 Troubleshooting

Bob changed much more than you askedRollback, then ask again: “Only change X. Don’t touch anything else.”
Bob keeps trying the same fixStop it. Roll back, add the exact error and the expected behaviour, or start a new chat.
The browser shows a blank pageOpen the developer console (F12 or ⌘ ⌥ I) and paste the red error message into the chat.
Bob says “done”, but it isn’tDescribe exactly what you see. Ask Bob to verify by running the code or the tests.
Bob uses a function that doesn’t exist“Are you sure? Show me where this is defined or documented.”
Python not found (Track B)Try python3 on macOS/Linux, or py on Windows.
Running low on BobcoinsUse smaller prompts and start new chats. If you’re out of Bobcoins, tell the host in the chat.
Show & tell (volunteers, screen share, 60 s): show what you built · the prompt that worked surprisingly well · where Bob went wrong, and how you got it back on track.
